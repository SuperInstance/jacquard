# Conformance

The spec's core promise is that an implementation in any language,
written from `spec/SPEC.md` + the golden vectors alone, reproduces
the reference kernel's record byte-for-byte. This directory is
where that promise is tested.

- `ts/` — an independent TypeScript implementation of canonical
  serialisation, envelope validation, the hash-chained log, and
  the log fold, written from the spec only (its author never read
  the Python source). `ts/GAPS.md` is its gap report: every place
  the spec underdetermined the implementation, and the reading
  chosen. Most gaps were fixed in the spec (section 2.1 exists
  because of this round); the report is kept as the record.
- `replay-log.json.gz` — the real gpu-queue replay as data:
  3,295 log entries plus the expected folded state hash.
- `full-log.json.gz` — a 25-entry log exercising every entry kind
  the kernel emits (generated by `gen_full_log.py`), with its
  expected folded state hash.
- `gen_full_log.py` — the full-log fixture generator (Python,
  coordinator-side tooling).

Run the checker (Node.js ≥ 22.18, builtins only):

```
cd conformance/ts && node check.ts
```

It prints one PASS/FAIL line per check and exits non-zero on any
failure. Since slice 19 (the full TypeScript port, `ts/kernel.ts`
— a deliberate port of the Python reference, the opposite method
from the slice-8 fold implementation beside it) there are **no
SKIP lines**: checks a–d cover the golden vectors (seal, entry
chain, checkpoint fold, envelope id); e–f the replay log; g the
all-kinds log; `vectors.definitions` and `vectors.state` execute
the dictionary and the sequencer end to end; `vectors.senses`
recomputes the contention/authority readings; `vectors.anchor`
verifies the Ed25519 checkpoint and runs the §15.5 procedure;
h proves the §12.1 shape signature identical to the Python
learner's over both proof-run corpora (against the committed
`signature-expectations.json`, generated by
`gen_signature_expectations.py`); i runs the stock-kernel half
of the slice 17 token-form battery.

Also here:

- `ts/cross-drill/` — the cross-language drill: one fixture
  stream (definitions, a standing-rule record, a proposal
  stream covering queue/release/reject/expire and the whole
  wait repertoire) driven through both sequencers; the logs
  and verdict streams come out byte-identical (see its
  `EVIDENCE.txt`; rerun with `python3 cross_drill.py`).
- `ts/verify-anchor.ts` — the TS twin of `tools/jqanchor.py
  verify`: a presented log, a checkpoint history, a pinned
  public key, one of the four §15.5 outcomes.
